# ديمو «اسأل وثيقتك» — RAG على الـ homelab

واجهة عربية: يرفع الزائر ملف PDF ويسأل عنه، فيجيب Gemini من الوثيقة فقط مع رقم الصفحة لكل معلومة.
التخزين والبحث الدلالي على `postgres_vector` الموجود عندك، والذكاء عبر Gemini API (لا يحتاج GPU).

**الحماية المدمجة:** كل زائر يرى ملفاته فقط، حد للأسئلة والرفع لكل IP، سقف يومي عام يحمي فاتورة الـ API،
حذف تلقائي للملفات بعد 24 ساعة، حد 5MB و40 صفحة و3 ملفات، والمنفذ مفتوح على الجهاز نفسه فقط.

---

## 1) انقل المجلد إلى الـ homelab

من اللابتوب، في المجلد الذي فككت فيه الملف المضغوط:

```bash
scp -r rag-demo homelab:~/
ssh homelab
cd ~/rag-demo
```

## 2) اعرف شبكة Docker واسم مستخدم Postgres الإداري

```bash
docker inspect postgres_vector --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'
docker exec postgres_vector printenv POSTGRES_USER
```

الأمر الأول يعطيك اسم الشبكة، والثاني اسم المستخدم الإداري (إن كان فارغاً فهو `postgres`).

## 3) أنشئ قاعدة بيانات ومستخدماً خاصين بالديمو

استبدل `ADMIN` باسم المستخدم الإداري، واختر كلمة مرور قوية بدل `كلمة_مرور_قوية`.
نفّذ الأوامر **واحداً واحداً**:

```bash
docker exec -it postgres_vector psql -U ADMIN -d postgres -c "CREATE USER rag_demo PASSWORD 'كلمة_مرور_قوية';"
docker exec -it postgres_vector psql -U ADMIN -d postgres -c "CREATE DATABASE rag_demo OWNER rag_demo;"
docker exec -it postgres_vector psql -U ADMIN -d rag_demo -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

قاعدة منفصلة ومستخدم محدود الصلاحيات يعنيان أن الديمو لا يلمس بياناتك الأخرى.

## 4) جهّز ملف الإعدادات

```bash
cp .env.example .env
nano .env
chmod 600 .env
```

املأ: `GEMINI_API_KEY`، و`PG_NETWORK` (من الخطوة 2)، وكلمة المرور داخل `DATABASE_URL`.

> **الطبقة المجانية:** الديمو مضبوط على نموذجين مجانيين: `gemini-3.1-flash-lite` للإجابات و`gemini-embedding-001` للفهرسة.
> - أنشئ **مشروعاً منفصلاً** في [Google AI Studio](https://aistudio.google.com) ومفتاحاً خاصاً بالديمو، لأن الحصص تُحسب لكل مشروع،
>   فلا يستهلك زوار الديمو حصة عملك على مشاريع العملاء.
> - افتح صفحة حدود الاستخدام في AI Studio، وانظر حد الطلبات اليومي (RPD) لنموذج `gemini-3.1-flash-lite`،
>   واجعل `DAILY_QUESTION_CAP` في `.env` أقل منه. الحصة اليومية تتجدد في منتصف الليل بتوقيت المحيط الهادئ (التاسعة صباحاً بتوقيت الجزائر شتاءً).
> - إن لم تفعّل الفوترة على هذا المشروع فلن تدفع شيئاً؛ عند نفاد الحصة يرى الزائر رسالة واضحة بدل الخطأ.
> - في الطبقة المجانية قد تستخدم Google المحتوى المرسل لتحسين منتجاتها، والواجهة تنبّه الزائر لذلك.
>   **لا تستخدم هذا المفتاح المجاني لمشاريع العملاء** التي تحتوي بيانات حقيقية.

## 5) شغّل

```bash
docker compose up -d --build
docker logs -f rag_demo        # انتظر "Application startup complete" ثم Ctrl+C
curl http://127.0.0.1:8010/health
```

إن ظهر `{"ok":true}` فالخادم يعمل. لتجربته بخصوصية قبل نشره، افتح طرفية جديدة على اللابتوب:

```bash
ssh -L 8010:127.0.0.1:8010 homelab
```

ثم افتح في متصفح اللابتوب: `http://localhost:8010`

**الرام:** الحاوية محدودة بـ 350MB. إن كان الجهاز مضغوطاً، أوقف ما لا تحتاجه، مثلاً: `docker stop nextcloud_app`.

## 6) اجعله متاحاً للعموم عبر Tailscale Funnel

```bash
sudo tailscale funnel --bg 8010
tailscale funnel status
```

في المرة الأولى قد يطلب منك تفعيل Funnel وشهادات HTTPS من لوحة تحكم Tailscale عبر رابط يظهر في الطرفية.
النتيجة رابط عام بالشكل `https://abdelhmid-vostro-1015.xxxx.ts.net`. هذا الرابط يوضع **في معرض الأعمال فقط**.

لإيقافه: `sudo tailscale funnel --bg 8010 off`

## 7) جهّز عمل المعرض

1. ارفع ملف PDF تجريبياً مناسباً (فاتورة، عقد، دليل منتج) واسأل 3 أسئلة، منها سؤال ليس في الوثيقة لتُظهر أن النظام لا يهلوس.
2. سجّل فيديو أقل من دقيقة لهذه التجربة، فهو الدليل الذي يبقى يعمل حتى لو توقف الجهاز.
3. أنشئ عملاً جديداً في معرضك على مستقل يحوي الرابط والفيديو والصور.

## التحديث وتغيير النماذج

- لتغيير النموذج: عدّل `CHAT_MODEL` (تأكد أنه ضمن الطبقة المجانية في صفحة الأسعار) في `.env` ثم `docker compose up -d`.
  **لا تغيّر** `EMBED_MODEL` أو `EMBED_DIM` بعد رفع ملفات إلا بعد حذف الجداول، لأن المتجهات القديمة لن تتوافق.
- بعد تعديل الكود: `docker compose up -d --build`.

## التحويل إلى نموذج محلي (Ollama / vLLM) أو أي مزود آخر

الكود لا يرتبط بـ Gemini: يكفي تغيير `.env` إلى `LLM_PROVIDER=openai` مع عنوان الخادم والنموذجين.
يعمل مع أي خادم متوافق مع OpenAI: Ollama، vLLM، LM Studio، وكذلك مزودون سحابيون بهذه الواجهة.
في `.env.example` مثال جاهز لـ Ollama.

- **Ollama على الجهاز نفسه:** اجعله يستمع على كل الواجهات بإضافة `OLLAMA_HOST=0.0.0.0` إلى خدمته،
  لأنه افتراضياً يستمع على `127.0.0.1` فقط فلا تصله الحاوية. والعنوان في `.env`: `http://host.docker.internal:11434/v1`
- **vLLM:** العنوان `http://عنوان_الخادم:8000/v1`، واسم النموذج كما شغّلته به.
- **`EMBED_DIM` يجب أن يطابق نموذج التضمين** (مثلاً `bge-m3` = 1024، و`nomic-embed-text` = 768).
  إن أخطأت، يظهر في `docker logs rag_demo` الرقم الصحيح.
- **عند تغيير نموذج التضمين يُعاد إنشاء الفهرس تلقائياً** وتُحذف الملفات المرفوعة، لأن متجهات نموذج لا تصلح للبحث بنموذج آخر.
- بعد أي تعديل في `.env`: `docker compose up -d`

> هذا الجهاز (Core 2 Duo بلا GPU) لا يصلح عملياً لتشغيل النماذج المحلية؛ هذه الميزة للسيرفرات الأقوى ولخوادم العملاء.

## حدود معروفة

- **ملفات PDF الممسوحة ضوئياً (صور)** لا يُستخرج منها نص في هذه النسخة.
- ملفات PDF العربية المحفوظة بترتيب العرض (كما يصدّرها Chrome وGoogle Docs) تُكتشف وتُصحَّح تلقائياً.
  في الصفحات متعددة الأعمدة أو الجداول قد تختلط أسطر الأعمدة، وهذا لا يؤثر عادة على دقة الإجابات.
  إن احتجت دعم الممسوح ضوئياً لاحقاً، يمكن إضافة استخراج عبر Gemini Vision.
- معالج Core 2 Duo يكفي هنا لأن الثقل كله عند Gemini، ولم تُستخدم مكتبات تتطلب AVX.
